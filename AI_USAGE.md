# Использование генеративного ИИ

## Минимальная техническая основа API и sequencer

- Участник: `M1`.
- Задача: подготовить к EK1 запускаемый HTTP API и sequencer, который присваивает каждой принятой команде единый возрастающий номер; реализацию matching engine и WAL оставить за явно обозначенными границами текущего этапа.
- Использование ИИ: с помощью Codex подготовлены первоначальная структура C++-проекта, HTTP-адаптер на Crow, обработка Crow JSON, валидация команд, потокобезопасный sequencer, автотесты, инструкции запуска и черновик связей `T-* → SR-* → D-* → будущая проверка`. Предложения ИИ требуют проверки и принятия ответственным участником.
- В проект вошло: исходный код API и sequencer в `include/` и `src/`, тесты в `tests/`, сборка в `CMakeLists.txt`, инструкция `docs/API.md`, требования, угрозы и решения `SR-01`–`SR-04`, `T-01`–`T-03`, `D-01`–`D-03` в `docs/API_SECURITY.md`, а также ссылки из `PROJECT.md`.
- Проверка человеком: прочитан и понят поток запроса от HTTP-адаптера через `CommandApi` к `CommandSequencer`; выполнена чистая сборка проекта по инструкции; запущены автотесты, включая конкурентную выдачу последовательности и отказ некорректной команде без расходования номера; вручную отправлены две корректные и одна некорректная HTTP-команда, проверены ответы и значение `last_sequence`; формулировки SR, T и D сверены с фактической архитектурой и границей текущей реализации.
- Связанный результат: `docs/API.md`, `docs/API_SECURITY.md`, `src/api.cpp`, `src/sequencer.cpp`, `src/main.cpp`, `tests/sequencer_tests.cpp` и соответствующий commit или pull request после его создания.
